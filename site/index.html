Re-ranking Amazon product search, ending in a 4B open model that ties a hosted LLM

A multi-stage re-ranker for ESCI Task 1: given a shopper's query and the products judged for it, put the relevant ones first. A gradient-boosted ranker orders each list; a fine-tuned model then re-orders its top 10. Every number on this page comes from a committed results file, measured once on all 8,956 test queries.

How the pipeline works

  1. Coarse rank

    LightGBM LambdaMART over 47 query–product features: BM25 and dense text similarity, CLIP image similarity, text overlap, and prices, ratings, categories and attributes from the ESCI-S scrape. It orders each query's whole judged list: 0.8579, level with the published baseline.

  2. Fine rank

    A slower model re-orders the coarse top 10. Cross-encoders fine-tuned on the training folds, open LLMs fine-tuned the same way, and a hosted LLM asked for a permutation were each measured, and each lies above the baseline.

  3. Blend

    Fixed-weight fusion, a learned combiner and a per-query selector over the stages. None beats the best stage it contains, so the deployed path stops at fine rank.

Serving the 4B model

One change a rung, each paired against the in-process reference on the validation queries. Latency is single-query on queries the server had not seen; throughput runs 16 queries at a time. No rung lost quality, so the fastest one, INT8, is deployed.

What the data got wrong

  • The Hugging Face mirror is the wrong split. It encodes the large-version split, 185,361 test judgements instead of 181,701. The loader asserts the official counts on every load.
  • The official evaluation script swaps the Substitute and Complement gains, which moves the random floor by over three points, more than most method gains. The floor is computed on every report, never quoted.
  • About half the ESCI-S image URLs point at a retired CDN bucket. Stripping one path segment makes them resolve.
  • Books store their image under a different key, so reading only image silently drops every book.
  • "Has an image" and "has a price" are ranking signals by accident: they record the 2022 scrape failing on a page, which a live system would not know. The behavioural ablation controls for them.

How it was measured

Validation folds were carved from the training queries by query and frozen before anything was tuned. Every model, prompt and serving rung was chosen on them; each test measurement sits behind a --final flag and was run once. Every NDCG is reported beside a random floor computed on the same queries, with bootstrap intervals over queries, and a test fails if the writeup quotes a figure that no committed results file contains.
